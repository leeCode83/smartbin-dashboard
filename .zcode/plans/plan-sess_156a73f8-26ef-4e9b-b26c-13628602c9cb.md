## Kesimpulan pemeriksaan awal

**Tidak ada endpoint yang perlu ditambah/diubah.** Semua data yang dibutuhkan UI saat ini sudah tersedia:
- `GET /api/smartbin/now` → data real-time terakhir (`gasValue`, `personDistance`, `fullDistance`, dll.)
- `GET/POST /api/smartbin/threshold` → baca & simpan threshold bau

Endpoint riwayat (`GET /api/smartbin`) dan average (`/api/smartbin/average`) **tidak dipasangkan** karena belum ada UI yang membutuhkannya. Tidak ada file migrasi Supabase baru. Jadi langsung ke wiring frontend.

## Kesepakatan desain (dari jawaban Anda)

- **Kapasitas tetap 1 tong, satu angka %**, dihitung di FE dari `fullDistance`:
  `% = clamp((TINGGI_TONG_CM − fullDistance) / TINGGI_TONG_CM × 100, 0, 100)`
  Konstanta `TINGGI_TONG_CM` di `app/page.tsx`, **default 30 cm — mohon koreksi angkanya kalau tinggi asli tong berbeda** (satu baris, mudah diubah).
- Kolom `fullnessOrganik/Anorganik/Kertas` diabaikan untuk sekarang (untuk masa depan).
- Mapping mock → API: `gas_adc` ← `gasValue`, `jarak_user_cm` ← `personDistance`. Logika `isBau` (vs threshold), `isServoBuka` (≤5 cm), `isFull` (≥100%) tetap sama.
- Polling tiap **5 detik**. Penanganan state: loading, error, dan `data: null` (tabel kosong → tampil "Menunggu data ESP32…"). Nilai `-1` (sensor error HC-SR04) ditampilkan "—".
